## 1. 为什么需要面向对象编程

### 1.1. 从一段"看起来还行"的代码开始

在上一课中，我们学习了列表、字典等数据结构。假设我们需要管理一台 Jetson 设备上的多个摄像头，每个摄像头有自己的编号、分辨率、帧率和开关状态。用我们已经学过的知识，可能会这样写：

```python
# 使用散装变量管理两个摄像头
camera1_id = 0
camera1_resolution = (1920, 1080)
camera1_fps = 30
camera1_is_on = True

camera2_id = 1
camera2_resolution = (1280, 720)
camera2_fps = 15
camera2_is_on = False

# 切换摄像头状态的函数
def toggle_camera(cam_id, cam_res, cam_fps, cam_status):
    if cam_status:
        print(f"摄像头 {cam_id} 已关闭 (分辨率: {cam_res}, 帧率: {cam_fps})")
        return False
    else:
        print(f"摄像头 {cam_id} 已开启 (分辨率: {cam_res}, 帧率: {cam_fps})")
        return True

# 使用
camera1_is_on = toggle_camera(camera1_id, camera1_resolution, camera1_fps, camera1_is_on)
camera2_is_on = toggle_camera(camera2_id, camera2_resolution, camera2_fps, camera2_is_on)
```

**这段代码有什么问题？**

1. **数据与操作分离**：摄像头的数据（编号、分辨率等）和操作（开关摄像头）散落各处。每增加一个摄像头，就要新增 4 个变量。
2. **传参容易出错**：`toggle_camera` 需要 4 个参数，如果不小心把不同摄像头的数据混在一起（如把 camera1 的帧率传给 camera2），Python 不会报错，但逻辑就错了。
3. **修改不方便**：想给摄像头增加一个新属性（如曝光值），需要修改所有相关的变量和函数。

### 1.2. 用字典能好一点，但不够

你可能想到用字典来组织：

```python
camera1 = {"id": 0, "resolution": (1920, 1080), "fps": 30, "is_on": True}
camera2 = {"id": 1, "resolution": (1280, 720), "fps": 15, "is_on": False}

def toggle_camera(camera):
    if camera["is_on"]:
        print(f"摄像头 {camera['id']} 已关闭")
        camera["is_on"] = False
    else:
        print(f"摄像头 {camera['id']} 已开启")
        camera["is_on"] = True

toggle_camera(camera1)
```

字典把数据打包了，但仍有缺陷：
- 别人可能写 `camera["Is_on"]`（大小写错误），bug 就产生了——字典没有结构约束
- 操作函数和数据仍然是分开的——代码任何角落都能修改 `camera["fps"]`
- 无法保证数据的有效性——有人可能设置 `camera["fps"] = -999`

### 1.3. 用类来解决问题

```python
class Camera:
    def __init__(self, cam_id, resolution, fps):
        self.cam_id = cam_id
        self.resolution = resolution
        self.fps = fps
        self.is_on = False

    def toggle(self):
        if self.is_on:
            self.is_on = False
            print(f"摄像头 {self.cam_id} 已关闭")
        else:
            self.is_on = True
            print(f"摄像头 {self.cam_id} 已开启 ({self.resolution[0]}x{self.resolution[1]}, {self.fps}FPS)")

# 使用——简洁清晰
cam1 = Camera(0, (1920, 1080), 30)
cam2 = Camera(1, (1280, 720), 15)

cam1.toggle()   # 摄像头 0 已开启 (1920x1080, 30FPS)
cam2.toggle()   # 摄像头 1 已开启 (1280x720, 15FPS)
cam1.toggle()   # 摄像头 0 已关闭
```

**对比总结：**

| | 散装变量 | 字典 | 类 |
|---|---|---|---|
| 数据组织 | 分散在多个变量中 | 打包在一个字典中 | 打包在对象中 |
| 操作与数据 | 分离 | 分离 | 绑定在一起 |
| 结构约束 | 无 | 无（键名可任意写） | 有（属性由 `__init__` 定义） |
| 创建多个实例 | 手动创建多组变量 | 手动创建多个字典 | `Camera(...)` 即可 |
| 代码可读性 | 差 | 一般 | 好 |

### 1.4. 为什么在 CV/AI 开发中特别需要类

在计算机视觉和 AI 开发中，我们经常遇到"有状态 + 有行为"的组合：

```
摄像头：     状态 = (编号, 分辨率, 帧率)，  行为 = 开关、拍照、录像
AI 模型：    状态 = (权重, 配置, 设备)，    行为 = 推理、加载、保存
检测结果：   状态 = (类别, 置信度, 边界框)， 行为 = 格式化输出、绘制边框
数据加载器： 状态 = (文件列表, 批次大小)，  行为 = 迭代、打乱、预处理
```

这些场景天然适合用类来组织——把相关的数据和操作打包在一起。

## 2. 类与对象的基本概念

### 2.1. 什么是类

**类（Class）** 是一个模板或蓝图，定义了某一类事物应该具有的**属性**（数据）和**方法**（行为）。类本身不是具体的事物，它描述的是"这一类事物是什么样的"。

举个例子：你可以把"摄像头"理解为一个类——它描述了所有摄像头共有的特征：都有编号、分辨率、帧率，都能被打开和关闭。但"摄像头"这个抽象概念本身并不能拍照——只有具体的"0号摄像头"才能。

### 2.2. 什么是对象

**对象（Object）** 是类的一个具体实例。每个对象都有自己独立的属性值，可以调用类中定义的方法。

"0号摄像头"是一个对象——它是"摄像头"这个类的具体实例，有自己独特的编号（0）、分辨率（1920x1080）、帧率（30）。

### 2.3. 类与对象的关系——一张图理解

```
        ┌──────────────────────────────┐
        │      class Camera            │  ← 蓝图（只定义一次）
        │                             │
        │  属性：cam_id, resolution,   │
        │        fps, is_on           │
        │  方法：toggle(), capture()   │
        └──────────────────────────────┘
                       │
          ┌────────────┴────────────┐
          │                         │
          ▼                         ▼
  ┌─────────────────┐     ┌─────────────────┐
  │  cam1 (对象)     │     │  cam2 (对象)     │  ← 实例（可以创建任意多个）
  │  cam_id = 0     │     │  cam_id = 1     │
  │  resolution =   │     │  resolution =   │
  │    (1920, 1080) │     │    (1280, 720)  │
  │  fps = 30       │     │  fps = 15       │
  │  is_on = False  │     │  is_on = False  │
  └─────────────────┘     └─────────────────┘

  同一个蓝图，但它们是两个独立的对象。
  cam1 的状态变化不影响 cam2。
```

## 3. 定义你的第一个类

### 3.1. 最简类——3行代码

```python
# 定义一个最简单的类
class Camera:
    pass

# 创建两个摄像头对象
cam1 = Camera()
cam2 = Camera()

print(type(cam1))        # <class '__main__.Camera'>
print(type(cam2))        # <class '__main__.Camera'>
print(cam1 is cam2)      # False——两个独立的对象
```

**逐行解释：**

| 代码 | 解释 |
|------|------|
| `class Camera:` | `class` 是关键字，`Camera` 是类名。定义了一个名为 Camera 的类 |
| `pass` | 占位符。表示"这个类暂时是空的"。Python 要求类体不能完全为空 |
| `cam1 = Camera()` | 用类创建对象（也叫**实例化**）。`Camera()` 会自动调用 `__init__` 方法 |

### 3.2. 类名命名规范

```python
# ✅ 大驼峰命名法（每个单词首字母大写）
Camera
VideoCapture
ModelInference
DetectionResult
ImagePreprocessor

# ✅ 变量和函数用小写 + 下划线
camera = Camera()
video_capture = VideoCapture()
detection_result = DetectionResult()
```

> ⚠️ **注意**：类名使用大驼峰（`Detector`），而变量和函数使用小写+下划线（`my_detector`）。这个约定在 Python 社区中广泛遵守。

## 4. __init__ 方法和 self 参数

`__init__` 和 `self` 是 Python 面向对象编程中最核心的两个概念。理解了它们，就理解了 OOP 的 80%。

### 4.1. __init__ —— 对象的"出厂设置"

`__init__` 是一个特殊方法，在创建对象时**自动被调用**，用于设置对象的初始状态。

```python
class Camera:
    def __init__(self, cam_id, resolution, fps):
        print(f"正在初始化摄像头 {cam_id}...")
        self.cam_id = cam_id
        self.resolution = resolution
        self.fps = fps
        self.is_on = False

# 创建对象时，__init__ 自动执行
cam1 = Camera(0, (1920, 1080), 30)
# 输出：正在初始化摄像头 0...
```

**关键理解**：你不需要手动调用 `cam1.__init__()`。Python 在 `Camera(0, (1920, 1080), 30)` 时自动做了三件事：

```
Camera(0, (1920, 1080), 30)
    ↓
1. 创建一个空的 Camera 对象
2. 调用这个对象的 __init__(self, 0, (1920, 1080), 30)
3. 返回这个对象
```

> 📌 **关于双下划线**：`__init__` 前后各有两个下划线。这是 Python 中"特殊方法"的命名约定（也叫"魔术方法"或"dunder 方法"）。你不能把它写成 `_init_`（单下划线）或 `init`（无下划线），那样 Python 就不会自动调用它了。

### 4.2. self —— 最重要的概念

**`self` = "当前这个具体的对象本身"**

```python
class Camera:
    def __init__(self, cam_id, fps):
        self.cam_id = cam_id     # self.cam_id = 这个对象的 cam_id 属性
        self.fps = fps           # self.fps = 这个对象的 fps 属性

    def show_info(self):
        print(f"摄像头 {self.cam_id}: {self.fps}FPS")

# 创建两个对象
cam1 = Camera(0, 30)
cam2 = Camera(1, 15)

cam1.show_info()    # 摄像头 0: 30FPS
cam2.show_info()    # 摄像头 1: 15FPS
```

**同一个 `self`，不同的指向：**

```
cam1.show_info()  →  self = cam1  →  self.cam_id = 0
cam2.show_info()  →  self = cam2  →  self.cam_id = 1
```

**self 的三个特征：**

| 特征 | 解释 |
|------|------|
| 自动传入 | 你写 `cam1.method(x)`，Python 把它变成 `Camera.method(cam1, x)` |
| 指向当前对象 | `cam1.method()` 中 self=cam1；`cam2.method()` 中 self=cam2 |
| 不是关键字 | 理论上你可以用别的名字（如 `this`），但整个 Python 世界都用 `self`，**不要改** |

### 4.3. 实例属性

在 `__init__` 中通过 `self.xxx = ...` 定义的属性称为**实例属性**。每个对象拥有自己独立的一份。

```python
class DetectionResult:
    def __init__(self, class_name, confidence, bbox):
        self.class_name = class_name    # 检测到的类别
        self.confidence = confidence    # 置信度
        self.bbox = bbox                # 边界框坐标 (x1, y1, x2, y2)

# 每个检测结果都有独立的属性值
det1 = DetectionResult("person", 0.95, (100, 200, 300, 500))
det2 = DetectionResult("car", 0.88, (50, 100, 400, 350))

print(f"检测到 {det1.class_name}，置信度 {det1.confidence}")  # 检测到 person，置信度 0.95
print(f"检测到 {det2.class_name}，置信度 {det2.confidence}")  # 检测到 car，置信度 0.88
```

## 5. 实例方法

### 5.1. 定义和调用方法

方法是定义在类内部的函数，第一个参数永远是 `self`：

```python
class Camera:
    def __init__(self, cam_id, resolution, fps):
        self.cam_id = cam_id
        self.resolution = resolution
        self.fps = fps
        self.is_on = False
        self.frame_count = 0

    def start(self):
        """开启摄像头"""
        if not self.is_on:
            self.is_on = True
            print(f"摄像头 {self.cam_id} 已启动")

    def stop(self):
        """关闭摄像头"""
        if self.is_on:
            self.is_on = False
            print(f"摄像头 {self.cam_id} 已停止 (共采集 {self.frame_count} 帧)")

    def capture_frame(self):
        """采集一帧图像（模拟）"""
        if not self.is_on:
            print(f"错误：摄像头 {self.cam_id} 未启动")
            return None
        self.frame_count += 1
        print(f"摄像头 {self.cam_id} 采集第 {self.frame_count} 帧")
        return f"frame_{self.frame_count}"

# 使用
cam = Camera(0, (1920, 1080), 30)
cam.start()
cam.capture_frame()   # 采集第 1 帧
cam.capture_frame()   # 采集第 2 帧
cam.stop()            # 摄像头 0 已停止 (共采集 2 帧)
```

### 5.2. 方法与普通函数的区别

| | 函数（Function） | 方法（Method） |
|---|---|---|
| 定义位置 | 独立定义在模块中 | 定义在类内部 |
| 第一个参数 | 任意 | 必须是 `self` |
| 调用方式 | `func(arg)` | `obj.method(arg)` |
| 访问对象数据 | 需要传参 | 通过 `self` 直接访问 |

**方法调用的本质：**

```python
class Demo:
    def show(self, message):
        print(f"show: {message}")

d = Demo()

# 这两种写法效果完全一样：
d.show("hello")          # ✅ 正常写法——推荐
Demo.show(d, "hello")    # 效果相同——self 显式传入，仅用于理解原理
```

## 6. 类属性 vs 实例属性

### 6.1. 类属性——所有对象共享

```python
class ModelConfig:
    # 类属性：所有模型配置共享
    default_device = "GPU"
    default_precision = "FP16"
    total_models_loaded = 0    # 统计一共加载了多少模型

    def __init__(self, model_name, input_size):
        # 实例属性：每个模型配置各自拥有
        self.model_name = model_name
        self.input_size = input_size

        # 修改类属性
        ModelConfig.total_models_loaded += 1

# 创建三个模型配置
yolo_config = ModelConfig("YOLOv5s", (640, 640))
resnet_config = ModelConfig("ResNet18", (224, 224))
mobilenet_config = ModelConfig("MobileNetV2", (224, 224))

# 类属性是所有对象共享的
print(yolo_config.default_device)       # "GPU"
print(resnet_config.default_device)     # "GPU"
print(mobilenet_config.default_device)  # "GPU"

# 修改类属性会影响所有实例
ModelConfig.default_device = "CPU"
print(yolo_config.default_device)       # "CPU"——跟着变了！

# 实例属性各自独立
print(yolo_config.model_name)           # "YOLOv5s"
print(resnet_config.model_name)         # "ResNet18"

# 类属性用于统计
print(f"共加载 {ModelConfig.total_models_loaded} 个模型")  # 共加载 3 个模型
```

### 6.2. 什么时候用类属性，什么时候用实例属性

| | 类属性 | 实例属性 |
|---|---|---|
| 定义方式 | 直接在类体中 `xxx = ...` | `self.xxx = ...` 在 `__init__` 中 |
| 共享范围 | 所有实例共享同一份 | 每个实例各自独立 |
| 典型用途 | 默认配置、计数器、常量 | 对象独有的数据 |
| 访问方式 | `ClassName.attr` 或 `obj.attr` | `obj.attr` |

**CV 场景示例：**

```python
class ImageClassifier:
    # 类属性：所有分类器共享的默认值
    supported_models = ["resnet18", "resnet50", "mobilenet_v2"]
    default_top_k = 5

    def __init__(self, model_name, threshold=0.5):
        if model_name not in ImageClassifier.supported_models:
            raise ValueError(f"不支持的模型：{model_name}")
        # 实例属性：每个分类器各自的配置
        self.model_name = model_name
        self.threshold = threshold
        self.inference_count = 0

    def classify(self, image_path):
        self.inference_count += 1
        # 模拟推理...
        print(f"使用 {self.model_name} 对 {image_path} 进行推理 (第 {self.inference_count} 次)")
```

## 7. 封装——保护数据，隐藏细节

### 7.1. 什么是封装

**封装（Encapsulation）** 是将数据（属性）和操作数据的方法绑定在一起，并对外部隐藏实现细节。外部只能通过类提供的公共方法（接口）与对象交互。

在 Python 中，使用**单下划线前缀** `_` 或**双下划线前缀** `__` 来表示属性是"私有的"，不应该被外部直接访问。

- `_attr`：约定俗成的"受保护"属性。提示"请勿直接访问"，但 Python 不会强制阻止
- `__attr`：名称会被 Python 改写（name mangling），更难被意外访问

### 7.2. 为什么需要封装

```python
class TemperatureSensor:
    """温度传感器——使用封装保护数据"""

    def __init__(self, location, min_temp=-20, max_temp=120):
        self.location = location
        self._min_temp = min_temp      # 受保护属性：温度下限
        self._max_temp = max_temp      # 受保护属性：温度上限
        self._temperature = 0.0        # 受保护属性：当前温度
        self._is_active = False        # 受保护属性：激活状态

    def activate(self):
        """激活传感器"""
        self._is_active = True
        print(f"传感器 {self.location} 已激活")

    def read_temperature(self):
        """读取温度（模拟）"""
        if not self._is_active:
            print(f"错误：传感器 {self.location} 未激活")
            return None
        import random
        self._temperature = round(random.uniform(20.0, 80.0), 1)
        return self._temperature

    def set_temperature_range(self, min_temp, max_temp):
        """安全地修改温度范围"""
        if min_temp >= max_temp:
            print("错误：最小值不能大于等于最大值")
            return
        self._min_temp = min_temp
        self._max_temp = max_temp
        print(f"温度范围已更新: {self._min_temp}°C ~ {self._max_temp}°C")

    def get_status(self):
        """获取传感器状态"""
        return {
            "location": self.location,
            "temperature": self._temperature,
            "active": self._is_active
        }

# 使用
sensor = TemperatureSensor("GPU")
sensor.activate()
temp = sensor.read_temperature()
print(f"当前温度: {temp}°C")

# ✅ 通过公共方法修改
sensor.set_temperature_range(-10, 100)

# ❌ 不应该直接访问受保护属性（虽然 Python 不会报错，但破坏了封装）
# sensor._temperature = 9999  # 不要这样做！
```

**封装的优点：**

1. **数据安全**：防止外部代码随意修改内部数据
2. **接口清晰**：外部只需要知道公开的方法，不需要了解内部实现
3. **易于维护**：修改内部实现不影响外部调用代码
4. **数据验证**：可以在方法中添加验证逻辑（如温度范围检查）

## 8. 继承——复用和扩展

### 8.1. 为什么需要继承

在 AI 项目中，我们经常需要处理不同类型的传感器（温度、湿度、光照、红外...）。它们有共同的特征（位置、状态、激活/停用），又有各自的特性（读取的数据类型不同）。

你有一个选择：
- **A）每个传感器都从头写一个类**——大量重复代码
- **B）写一个基础传感器类，然后让具体的传感器继承它**——只写不同的部分

继承 = **在已有类的基础上，添加或修改功能。**

### 8.2. 父类与子类

```python
# 父类（基类）：定义所有传感器的共同特征
class BaseSensor:
    def __init__(self, location, model_name):
        self.location = location
        self.model_name = model_name
        self.is_active = False

    def activate(self):
        self.is_active = True
        print(f"[{self.model_name}] 位于 {self.location} 已激活")

    def deactivate(self):
        self.is_active = False
        print(f"[{self.model_name}] 位于 {self.location} 已停用")

    def get_info(self):
        return f"{self.model_name} @ {self.location}"

# 子类 1：温度传感器——继承 BaseSensor，添加温度读取功能
class TemperatureSensor(BaseSensor):
    def __init__(self, location, model_name, unit="Celsius"):
        super().__init__(location, model_name)  # 调用父类的 __init__
        self.unit = unit
        self._temperature = 0.0

    def read(self):
        if not self.is_active:
            print("错误：传感器未激活")
            return None
        import random
        self._temperature = round(random.uniform(20.0, 85.0), 1)
        print(f"温度读数 ({self.location}): {self._temperature}°{self.unit[0]}")
        return self._temperature

# 子类 2：湿度传感器——继承 BaseSensor，添加湿度读取功能
class HumiditySensor(BaseSensor):
    def __init__(self, location, model_name):
        super().__init__(location, model_name)
        self._humidity = 0.0

    def read(self):
        if not self.is_active:
            print("错误：传感器未激活")
            return None
        import random
        self._humidity = round(random.uniform(30.0, 90.0), 1)
        print(f"湿度读数 ({self.location}): {self._humidity}%")
        return self._humidity

# 子类 3：光照传感器——继承 BaseSensor，添加光照读取功能
class LightSensor(BaseSensor):
    def __init__(self, location, model_name, max_lux=100000):
        super().__init__(location, model_name)
        self.max_lux = max_lux
        self._lux = 0

    def read(self):
        if not self.is_active:
            print("错误：传感器未激活")
            return None
        import random
        self._lux = round(random.uniform(0, self.max_lux), 0)
        print(f"光照读数 ({self.location}): {self._lux} lux")
        return self._lux

# 使用
temp_sensor = TemperatureSensor("CPU", "DS18B20")
hum_sensor = HumiditySensor("机箱", "DHT22")
light_sensor = LightSensor("室外", "BH1750", max_lux=50000)

temp_sensor.activate()      # [DS18B20] 位于 CPU 已激活    ← 继承自 BaseSensor
hum_sensor.activate()       # [DHT22] 位于 机箱 已激活      ← 继承自 BaseSensor
light_sensor.activate()     # [BH1750] 位于 室外 已激活     ← 继承自 BaseSensor

temp_sensor.read()          # 温度读数 (CPU): 56.3°C       ← 子类特有
hum_sensor.read()           # 湿度读数 (机箱): 67.2%        ← 子类特有
light_sensor.read()         # 光照读数 (室外): 32451 lux    ← 子类特有

print(temp_sensor.get_info())   # DS18B20 @ CPU            ← 继承自 BaseSensor
```

**语法**：`class 子类名(父类名):`

### 8.3. super() —— 调用父类的方法

当子类需要自己的 `__init__` 时，它通常还需要调用父类的 `__init__`：

```python
class BaseSensor:
    def __init__(self, location, model_name):
        self.location = location
        self.model_name = model_name
        self.is_active = False
        print(f"BaseSensor.__init__ 完成: {model_name}")

class TemperatureSensor(BaseSensor):
    def __init__(self, location, model_name, unit="Celsius"):
        # ✅ 调用父类的 __init__，确保 location 和 model_name 被正确设置
        super().__init__(location, model_name)
        self.unit = unit         # TemperatureSensor 特有的属性
        print(f"TemperatureSensor.__init__ 完成: 单位={unit}")

sensor = TemperatureSensor("GPU", "TMP102")
# 输出：
# BaseSensor.__init__ 完成: TMP102
# TemperatureSensor.__init__ 完成: 单位=Celsius

print(sensor.location)    # "GPU"     ← 来自 BaseSensor.__init__
print(sensor.unit)        # "Celsius" ← 来自 TemperatureSensor.__init__
```

**super().__init__() 做了什么？**

```
super().__init__(location, model_name)
    ↓
"找到我的父类（BaseSensor），调用它的 __init__ 方法"
    ↓
BaseSensor.__init__(self, location, model_name)
    ↓
self.location = location   ← 这行在 BaseSensor.__init__ 中执行
self.model_name = model_name
self.is_active = False
```

> ⚠️ **重要警告**：如果子类定义了 `__init__` 但**忘记**调用 `super().__init__()`，父类的初始化代码就不会执行，父类中定义的属性将不会被设置，程序可能报 `AttributeError`。

### 8.4. 继承的现实世界类比

```
父类 = "家用电器"（定义了通电、开关等基本能力）
```

## 9. 方法重写

### 9.1. 什么是方法重写

**方法重写（Override）**：子类定义一个和父类**同名**的方法，子类的方法会"覆盖"父类的。

```python
class BaseSensor:
    def __init__(self, location):
        self.location = location

    def get_report(self):
        """默认的报告格式"""
        return f"传感器位置: {self.location}"

class TemperatureSensor(BaseSensor):
    def __init__(self, location):
        super().__init__(location)
        self._temperature = 25.0

    def get_report(self):       # ← 和父类同名 → 重写！
        """温度传感器专属的报告格式"""
        return f"温度传感器 @ {self.location}: {self._temperature}°C"

class HumiditySensor(BaseSensor):
    def __init__(self, location):
        super().__init__(location)
        self._humidity = 60.0

    def get_report(self):       # ← 重写父类的 get_report
        return f"湿度传感器 @ {self.location}: {self._humidity}%"

# 使用
sensors = [
    TemperatureSensor("CPU"),
    HumiditySensor("机箱"),
    BaseSensor("未知位置")       # 没有重写的使用父类默认
]

for s in sensors:
    print(s.get_report())

# 输出：
# 温度传感器 @ CPU: 25.0°C         ← 子类的版本
# 湿度传感器 @ 机箱: 60.0%         ← 子类的版本
# 传感器位置: 未知位置              ← 父类的默认版本
```

### 9.2. CV 场景示例：不同的 AI 模型有不同的推理方式

```python
class BaseModel:
    """AI 模型基类"""
    def __init__(self, model_path, device="GPU"):
        self.model_path = model_path
        self.device = device
        self.is_loaded = False

    def load(self):
        self.is_loaded = True
        print(f"加载模型: {self.model_path} (设备: {self.device})")

    def predict(self, input_data):
        """基类的 predict 只是占位，子类必须重写"""
        raise NotImplementedError("子类必须实现 predict 方法！")

class ObjectDetector(BaseModel):
    """目标检测模型"""
    def predict(self, input_data):     # ← 重写 predict
        if not self.is_loaded:
            raise RuntimeError("模型未加载！")
        # 模拟检测
        return [
            {"class": "person", "confidence": 0.92, "bbox": (100, 200, 300, 500)},
            {"class": "car", "confidence": 0.87, "bbox": (50, 100, 400, 350)},
        ]

class ImageClassifier(BaseModel):
    """图像分类模型"""
    def predict(self, input_data):     # ← 重写 predict（不同的实现）
        if not self.is_loaded:
            raise RuntimeError("模型未加载！")
        # 模拟分类
        return {"class": "cat", "confidence": 0.956}

# 使用——通过统一的接口调用不同的模型
detector = ObjectDetector("yolov5s.pt")
detector.load()
results = detector.predict("image.jpg")
print(f"检测到 {len(results)} 个目标")

classifier = ImageClassifier("resnet18.pt")
classifier.load()
result = classifier.predict("cat.jpg")
print(f"分类结果: {result['class']} (置信度: {result['confidence']})")
```

> 📌 **方法重写的核心价值**：通过统一的接口（`predict`）调用不同类型的模型，每种模型以自己的方式实现。外部调用者不需要关心内部细节。

## 10. 综合示例：AI 模型推理管理器

让我们把学到的所有 OOP 概念整合到一个实际的边缘 AI 场景中：

```python
import time
import random

# ===================== 基类 =====================
class BaseInferenceEngine:
    """推理引擎基类——定义所有推理引擎的通用接口"""

    engine_count = 0                      # 类属性：统计创建的引擎数量

    def __init__(self, model_name, device="CPU"):
        self.model_name = model_name
        self.device = device
        self._is_initialized = False      # 受保护属性：初始化状态
        self._inference_count = 0         # 受保护属性：推理次数
        BaseInferenceEngine.engine_count += 1

    def initialize(self):
        """初始化引擎（加载模型、分配内存等）"""
        self._is_initialized = True
        print(f"[{self.model_name}] 已在 {self.device} 上初始化")

    def infer(self, input_data):
        """执行推理——子类需要重写"""
        raise NotImplementedError("子类必须实现 infer 方法")

    def get_stats(self):
        """获取统计信息"""
        return {
            "model": self.model_name,
            "device": self.device,
            "inferences": self._inference_count,
            "initialized": self._is_initialized
        }

# ===================== 子类：目标检测引擎 =====================
class DetectionEngine(BaseInferenceEngine):
    """目标检测推理引擎"""

    def __init__(self, model_name, device="CPU", confidence_threshold=0.5):
        super().__init__(model_name, device)      # ← 调用父类 __init__
        self.confidence_threshold = confidence_threshold

    def infer(self, input_data):                   # ← 重写 infer
        if not self._is_initialized:
            raise RuntimeError(f"[{self.model_name}] 未初始化！")
        self._inference_count += 1

        # 模拟检测推理
        time.sleep(0.01)  # 模拟推理延迟
        detections = [
            {"class": "person", "conf": random.uniform(0.5, 0.99)},
            {"class": "car", "conf": random.uniform(0.5, 0.99)},
            {"class": "bicycle", "conf": random.uniform(0.5, 0.99)},
        ]
        # 过滤低置信度的结果
        return [d for d in detections if d["conf"] >= self.confidence_threshold]

# ===================== 子类：图像分类引擎 =====================
class ClassificationEngine(BaseInferenceEngine):
    """图像分类推理引擎"""

    def __init__(self, model_name, device="CPU", top_k=5):
        super().__init__(model_name, device)
        self.top_k = top_k

    def infer(self, input_data):                   # ← 重写 infer
        if not self._is_initialized:
            raise RuntimeError(f"[{self.model_name}] 未初始化！")
        self._inference_count += 1

        # 模拟分类推理
        classes = ["cat", "dog", "bird", "fish", "rabbit", "hamster", "turtle"]
        results = []
        for i, cls in enumerate(random.sample(classes, self.top_k)):
            results.append({
                "rank": i + 1,
                "class": cls,
                "confidence": round(random.uniform(0.5, 0.99) * (1 - i * 0.1), 3)
            })
        return sorted(results, key=lambda x: x["confidence"], reverse=True)

# ===================== 使用 =====================
# 创建不同类型的推理引擎
detector = DetectionEngine("YOLOv5s", device="GPU", confidence_threshold=0.6)
classifier = ClassificationEngine("ResNet50", device="GPU", top_k=3)

# 统一的初始化流程（继承自 BaseInferenceEngine）
detector.initialize()
classifier.initialize()

# 统一的推理接口（各自重写的 infer 方法）
det_results = detector.infer("street_scene.jpg")
print(f"检测结果: {det_results}")

cls_results = classifier.infer("animal.jpg")
for r in cls_results:
    print(f"  Top-{r['rank']}: {r['class']} ({r['confidence']})")

# 统一的统计接口（继承自 BaseInferenceEngine）
print(f"\n统计信息:")
print(f"  检测引擎: {detector.get_stats()}")
print(f"  分类引擎: {classifier.get_stats()}")
print(f"  总引擎数: {BaseInferenceEngine.engine_count}")
```

**这个综合示例展示了：**

| OOP 概念 | 在示例中的体现 |
|---|---|
| 类与对象 | `DetectionEngine`、`ClassificationEngine` 是类；`detector`、`classifier` 是对象 |
| `__init__` | 每个类都有自己的 `__init__`，初始化不同的属性 |
| `self` | 每个方法都通过 `self` 访问当前对象的属性 |
| 实例属性 | `model_name`、`device`、`confidence_threshold` 每个对象各自独立 |
| 类属性 | `engine_count` 被所有实例共享，用于统计 |
| 封装 | `_is_initialized`、`_inference_count` 用下划线标记为内部属性 |
| 继承 | `DetectionEngine(BaseInferenceEngine)` 继承基类的所有能力 |
| `super()` | 子类的 `__init__` 通过 `super().__init__()` 调用父类初始化 |
| 方法重写 | `infer()` 在每个子类中重写，实现不同的推理逻辑 |

| 对象（object） | 按照蓝图造出来的具体东西 |
| `__init__` | 创建对象时自动调用，设置初始状态 |
| `self` | "当前这个对象"，指向调用方法的那个实例 |
| 实例方法 | 类里面的函数，第一个参数永远是 `self` |
| 类属性 | 所有实例共享的属性 |
| 实例属性 | 每个对象独立拥有的属性 |
| 封装 | 用 `_` 前缀保护数据，通过公共方法访问 |
| 继承 | `class 子类(父类):` 复用父类的代码 |
| `super()` | 调用父类的方法（特别是 `__init__`） |
| 方法重写 | 子类定义同名方法，覆盖父类的行为 |

面向对象编程不是 Python 的"高级特性"，而是 AI 工程中的**基础设施**。后续你会学到 PyTorch 的 `nn.Module`，它本质上就是一个精心设计的父类——你写的每一个神经网络，都是在继承它并重写 `forward` 方法。
